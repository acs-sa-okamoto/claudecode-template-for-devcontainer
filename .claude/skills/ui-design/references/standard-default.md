# 社内標準（業務アプリ版）v1.0

> ui-design が使う、業務アプリの画面の標準。**plan（新規）は、これを写してプロジェクトの `docs/ui/standard.md` を作る。**
> 値は `assets/tokens.css`、部品の見た目は `assets/components.css`、当てはめた見本は `assets/standard-mock.html`（#list・#form・#empty・#dialog）。
> 元にしたもの: slide-maker の標準デザイン（`slide-maker/assets/design-directions.md`。ダスティブルー×黒×白・角丸なし・BIZ UDPゴシック）を、2026-11 に画面向けに直した。スライドの標準は slide-maker、画面の標準はここで別々に管理する。
> **プロジェクトの standard.md で決めたことは、ここより優先する。** ただし「アクセシビリティの最低線」は下げない。

## コンセプト

**ダスティブルー×黒×白。** 鮮やかなアクセント色を使わず、強調は黒の太字とサイズで作る。角丸なし・影なし・グラデーションなし。左揃え・左重心。**画面の文字はすべて情報**（意匠としての英語は使わない）。

## スライドの標準から変えたところ

| スライド | 画面 | 理由 |
|---|---|---|
| 補足の文字 `#6B7280` | 補足の文字は `#4B5563`（`--color-text-sub`） | `#6B7280` は淡青の上で 3.3:1 しかなく、本文の基準 4.5:1 に届かない。画面では淡青の上にも補足が載る。`#4B5563` なら白 7.6:1・淡青 5.2:1 |
| 淡青は表紙と締めの全面 | 淡青はナビゲーションの地・選択中の行 | 画面の「構造」を示す色として使う |
| 3色だけ | 3色＋同じ色相の濃淡＋意味色 | マウスを乗せた・選んだ・無効などの状態を、新しい色相を足さずに表すため（淡青（弱）`#E5ECF2`・黒の明るめ `#2B3038`） |
| 縦ラベル（英語）・右下タグ | 使わない | 画面の文字はすべて情報。C 層（AI っぽさ）の「見出しの上の英字ラベル」にも当たる |
| Segoe UI（欧文の意匠） | 使わない | 数字・英字も BIZ UDPゴシックでそろえる |
| 本文 12.5〜14pt | 本文 16px・表 14px | 画面を読む距離に合わせる |
| CTA = 白地＋黒の細枠 | 副ボタン（主ボタンは黒地に白文字） | 主役の操作をひと目で分かるようにする |

### 色の決まり

- 鮮やかな色を足さない。強調は黒の太字とサイズで作り、**1画面1か所**にする。
- 淡青は構造の色。淡青と淡青（弱）の上に置く文字は `--color-text` と `--color-text-sub` だけ。
- 意味色は状態を表すときだけ使う。**必ず文字（とアイコン）を添え、色だけで伝えない。**
- 部品の輪郭（入力欄・ボタン）は `--color-border-control` か `--color-action`。区切り線の色を輪郭に使わない。

## 文字

- **書体:** BIZ UDPゴシック（Windows 10 以降に標準で入っている）。無い環境では Yu Gothic UI → Yu Gothic → メイリオ → ヒラギノ角ゴ → Noto Sans JP の順。等幅（`--font-mono`）はコードと ID だけ。
- **大きさの段階**（この6つだけを使う）:

  | 大きさ | トークン | 使う所 |
  |---|---|---|
  | 28px | `--font-size-2xl` | ページの題名 |
  | 22px | `--font-size-xl` | 見出し |
  | 18px | `--font-size-lg` | 小見出し・ダイアログの題名・ナビの製品名 |
  | 16px | `--font-size-md` | 本文・入力・ボタン |
  | 14px | `--font-size-sm` | 表・ラベル・補足・パンくず |
  | 12px | `--font-size-xs` | 注記・バッジ（これより小さくしない） |

- **太さ:** 400 と 700 だけ。
- **行間:** 本文 1.7／表・ボタン・ラベル 1.5／見出し 1.4。
- **字間:** 0.02em（見出しも同じ。広げすぎない）。

## 余白と形

- 余白は 4px 刻みの8段階（4・8・12・16・24・32・48・64px）だけを使う。
- 関係の強いものは近く、弱いものは遠くに置く。目安はラベルと入力欄 4px、項目どうし 24px、まとまりどうし 48px。
- 画面の端の余白は、広い画面で 32px、767px 以下で 16px。
- **角丸なし。** 円は円のまま使ってよい（アイコン・状態の点）。影なし・グラデーションなし。
- 浮かせたいもの（ダイアログ・一時的な知らせ）は、影の代わりに黒の細枠で区切る。

## 部品

### ボタン

| 種類 | 見た目 | 使う場面 |
|---|---|---|
| **主ボタン** | 黒地（`#0F1115`）に白文字・太字。マウスを乗せると `#2B3038` | その画面の主役の操作。**1画面に1つ** |
| **副ボタン** | 白地に黒の細枠（1px）と黒文字。スライドの CTA と同じ形。乗せると淡青（弱）の地 | 主役以外の操作（下書き保存・絞り込む・キャンセル） |
| 文字ボタン | 枠なし・下線付きの黒文字 | 表の中の軽い操作（内容を見る）・フォームのキャンセル |
| 危険ボタン | 赤地（`#DC2626`）に白文字 | 取り消せない操作を確かめるダイアログの実行ボタンだけ |
| 危険の入口 | 白地に赤の細枠と赤文字 | 詳細画面の「削除」など、確認ダイアログを開くボタン |
| 無効 | 灰の地（`#E5E7EB`）に `#6B7280` の文字 | 押せない理由を近くに書く |

- 大きさ: 高さ 40px（表の中など詰めたい所だけ 32px）、左右の余白 16px、文字 16px の太字。
- 押せる範囲は 24×24px 以上（WCAG 2.2）。アイコンだけのボタンは 40×40px にし、`aria-label` を付ける。
- フォーカス: 黒の 2px の枠を 2px 離して描く（全部品共通）。
- 並び: フォームの末尾は左揃えで「主 → 副 → キャンセル」。ダイアログは右揃えで「キャンセル → 実行」。
- 名前: 何が起きるかを動詞で書く（「申請する」「保存する」「削除する」）。「OK」「はい」「送信」は使わない。キャンセル・閉じる・戻るはそのまま使う。

### 入力

- ラベルは入力欄の上（14px の太字）。必須の項目には「必須」の文字の印を付ける（色や `*` だけにしない）。任意の項目には何も付けない。
- 入力欄: 高さ 40px、白地、`#6B7280` の 1px の枠、文字 16px（スマホで勝手に拡大されない大きさ）。
- 説明はラベルか入力欄のすぐ下に書く（14px・補足の色）。placeholder は例を見せるだけで、説明の代わりにしない。
- エラーの見せ方:
  - 入力欄の枠を 2px の赤にし、すぐ下に赤の太字で「何が違うか＋どう直すか」を書く。
  - 送信したときは、画面の上にもまとめを出し、各項目へのリンクを付ける。
- 金額・数量は右揃え。短い値の欄（金額・日付）は幅を 240px に絞る。
- チェックボックスは 20px。文字の部分を押しても切り替わるようにする。

### 表

- 見出し行は太字で、下に 2px の黒線。本文の行は 1px の区切り線。
- マウスを乗せた行は淡青（弱）。選んだ行は淡青に、左の黒い帯を付ける。
- 数値の書き方:
  - 右揃え・桁区切り（12,480）・等幅の数字（tabular-nums）。
  - 単位は見出しに書く（「金額（円）」）。
- 文字は 14px、行の上下の余白は 12px。縞模様は使わない（行が多くて追いにくいときだけ、淡青（弱）を使う）。
- 狭い画面では表だけを横に動かし、画面全体は横に動かさない。列を減らせるなら減らす。
- 0件のときは、表の代わりに「空の画面」の案内を出す。

### ナビゲーションとページの頭

- 左のナビ（幅 240px）の地は淡青。選んでいる項目は、白地・左の黒い帯・太字で示す（色だけで示さない）。
- 767px 以下ではナビを隠し、上の帯（淡青）に「メニュー」ボタンを置く。
- ページの頭は、パンくず（14px・補足の色）→ 題名（28px）→ 1〜2行の説明（補足の色）の順。主ボタンは題名の右に置き、狭い画面では下に回す。
- 題名の下に罫線や飾りを付けない。

### 状態の知らせ

- **バッジ:** 淡青（弱）の地に黒の太字 12px、左に意味色の帯。状態の言葉は必ず文字で書く。
- **お知らせ（画面の中）:** 白地・細枠・左の意味色の帯・アイコン。題名に何が起きたか、本文に次にすることを書く。
- **一時的な知らせ（トースト）:**
  - 右下に出す。成功だけ5秒で消え、エラーは閉じるまで残す。
  - 文言は操作の名前とそろえる（「保存する」→「保存しました」）。
- **読み込み中:**
  - 300ms 以上かかるときだけ出す。中身の形をした淡青（弱）の帯を置き、動かさない。
  - ボタンを押した後は、そのボタンを無効にして「保存しています…」と出す。
- **空の画面:** 何が無いか、次にすること、（あれば）主ボタン。絵は使わない。
- **確認ダイアログ:**
  - 出すのは取り消せない操作だけ。題名は「〜しますか？」にする。
  - 本文には、何が消えるか・戻せるかを書く。実行ボタンには操作の名前（「削除する」）を書く。

### ダイアログ

- 白地に黒の細枠（影なし）。後ろは黒の 40%。幅は 560px まで。
- 開いたらダイアログの中にフォーカスを移し、外へ出さない。後ろの画面は操作できないようにする（`inert`）。
- Esc で閉じる。閉じたら、開いたボタンへフォーカスを戻す。

### アイコン

- 線のアイコン（太さ 2px・角は四角）を、意味を補うときだけ使う。操作には必ず文字を添える。
- 飾りのアイコン・絵文字は使わない。

### グラフ（ダッシュボード）

- 系列は淡青 → 補足の色 → 黒の濃淡で分ける。意味色は状態（目標未達など）を表すときだけ使う。
- 凡例を文字で添え、色だけで系列を区別しない。

## 画面の型

- **一覧＋詳細:** 一覧は「絞り込み → 件数 → 表 → ページ送り」の順。行の件名から詳細へ進む。
- **入力:** 1列のフォーム（最大 640px）。関係する項目は、まとまりごとに見出しで区切る。
- **確認:** 取り消せない操作だけ、ダイアログで確かめる。
- **ダッシュボード:** 数字は大きく（28px）し、単位と比べる相手（前月など）を添える。

## 文言

- です・ます調で、短く書く。システムの言葉ではなく利用者の言葉を使う（「レコード」ではなく「申請」）。
- ボタンは何が起きるかを動詞で書く。同じ操作は全画面で同じ言葉にし、完了の知らせも同じ言葉にする（「申請する」→「申請しました」）。
- エラーは「何が起きたか」と「どうすればよいか」を書く。謝罪の言葉で始めない。「エラーが発生しました」だけで終わらせない。
- 空の画面では、次の行動に誘う。
- 書式:
  - 日付は 2026/11/02、時刻は 14:05（24時間）。曜日が要るときは 2026/11/02（月）。
  - 金額は「12,480」と書き、単位（円）を添える。
- 文字の使い分け:
  - 数字・英字は半角、カタカナは全角。
  - 和文と英数字の間に空白を入れない。
  - 括弧と句読点は全角（「」（）、。）。

## 日本語の組み方

- 本文の1行は 40 字前後まで（`max-width: 40em`）。フォームの説明も同じ。
- 行間は 1.7、段落の間は 16px。
- 見出しを不自然な位置で折り返さない（`word-break: auto-phrase`。効かないブラウザでは、文の区切りで改行を入れる）。
- 斜体は使わない（和文に斜体は無い）。強調は太字にする。
- 長い英数字（URL・ID）は `overflow-wrap: anywhere` で折り返す。
- 下線はリンクだけに使う。

## アクセシビリティの最低線（WCAG 2.2 AA）

- コントラスト: 文字は 4.5:1 以上（大きな文字は 3:1）、部品の輪郭と状態は 3:1 以上（上の表のとおり）。
- キーボードだけで全部の操作ができ、フォーカスが見える（黒の 2px）。
- 押せる範囲は 24×24px 以上（主な操作は 40px）。
- 入力にはラベルを付ける。エラーは文字で伝え、色だけにしない。
- 動きを減らす設定を尊重する。登場の動きや点滅は使わず、色の切り替えも 120ms までにする。
- 暗い画面（ダークモード）は、既定では作らない。必要な案件は standard.md で決める。

## Do / Don't

**Do**
- 強調は黒の太字とサイズで、1画面1か所にする。
- 淡青は構造の色として使う。
- 状態は文字と印で伝える。
- 主ボタンは1画面に1つ。

**Don't**
- 鮮やかなアクセント色を持ち込まない。
- 角丸・影・グラデーションを使わない。
- 見出しの上に英字のラベルを置いたり、題名の下に罫線を引いたりしない。
- 色だけで意味を伝えない。
- エラー文を謝罪から始めない。

## プロジェクトでの使い方（写さない節）

- **plan（新規）:**
  - この標準を `docs/ui/standard.md` に写す（`templates/standard.md` の形。写した版と日付を書く）。
  - 製品の情報と例外を足す。
  - `assets/tokens.css` を実装のトークンファイルの元にし、`assets/components.css` を部品の見た目の元にする。
- **変えてよいこと:** 製品に合わせた例外（理由と信頼性を書く）。**変えてはいけないこと:** コントラストとアクセシビリティの最低線。
- **別のデザインの見本を指定されたとき:** slide-maker の design-directions.md「例外: 別デザインの見本を指定された場合（リファレンス翻訳）」と同じ手順で、この標準を土台に上書きする。ゼロから発明せず、ブランドの複製もしない。
- **この標準を直したとき:** 版を上げる（v1.1 …）。プロジェクトの standard.md は写した時点の版のまま残る（勝手には変わらない）。新しい版を取り込みたいプロジェクトは `/ui-renewal` で行う。

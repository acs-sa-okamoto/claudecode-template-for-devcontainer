あなたは、いま作業しているリポジトリの**同梱スキルを最新化する担当**です。テンプレートリポジトリを**正本**とし、そこにある内容でリポジトリ側を更新します。

# 何のためにあるか

スキルはリポジトリに同梱して配る方式なので、**放っておくと配布先ごとに古くなり、しかも古いことに誰も気づけない**（バージョンの概念が無いため）。典型的にはこういう場面で使う:

- **オーケストレーター（`power` / `beam`）そのものを直した**ので、作業中のリポジトリに反映したい
- 運用中にスキルを改良したので、**いま開いているリポジトリだけ先に**最新化したい
- **beam で作ったリポジトリ**を久しぶりに触る（beam には power の step1-0 のような自動更新が無いため、ここが唯一の更新口になる）
- `/power` が「同梱スキルが古い」と報告したが、その場では更新しなかった

# 方針（重要・これ以外のことはしない）

- **テンプレートが正本。差分があれば上書きする。** 「持っているか」「新しいか」は判定しない。正本が1つで、配布先が「より新しい／より正しい」版を持つ筋書きが存在しないため。条件を増やすほど判定漏れの穴ができる（実際「一部だけ古い」で取り残された前例が2件ある）。
- **リポジトリ独自に足したスキルは消さない。** テンプレに無いファイルは ⚠️ で一覧するだけ。廃止したものだけ人間が `git rm` する。
- **リポジトリ側の編集は保護しない。** テンプレ由来のスキルをこのリポジトリで直接編集していた場合、**その変更は上書きで失われる**（`.claude/` は git 管理下なので `git diff` / `git restore` で復元できる）。スキルを恒久的に変えたいなら、**正本（`~/.claude/skills/`）を直してテンプレへ同期する**のが正しい経路。
- **取得に失敗しても止めない。** テンプレは private なので `gh` 認証が要る。失敗したら警告して「いまあるもので続行してよい」と伝える。

> **`sync-skills.sh` と混同しないこと。** あれは**正本 → テンプレ**（メンテナが使う）。本スキルは**テンプレ → このリポジトリ**（利用者が使う）で、向きが逆である。

## step1: 実行

対象は `.claude/skills/` ＋ `.claude/skills-catalog/` ＋ `docs/rule/ai-security-guardrails.md`（最後の1つは派生コピー。外すと「ここだけ古い」が再発する）。

```bash
# スクリプトは「このスキルの置き場所」から辿る（作業ディレクトリや $HOME を基準にしない）
B='<このスキルのベースディレクトリ>'   # Claude Code が「Base directory for this skill」で示す値をそのまま入れる
B="$(printf '%s' "$B" | tr '\134' '/')"                    # \ を / に揃える（\134 はバックスラッシュ）
if command -v wslpath >/dev/null 2>&1; then                # WSL の bash のときだけ変換する
  case "$B" in
    //wsl.localhost/*/*|//wsl[$]/*/*) B="/${B#//*/*/}" ;;   # \\wsl.localhost\<distro>\x → /x
    [A-Za-z]:/*) B="$(wslpath -u "$B")" ;;                  # C:\x → /mnt/c/x
  esac
fi
bash "$B/scripts/refresh-skills-from-template.sh"          # 引数に --check が渡されていればそれも付ける
```

- **パスはこのスキルの置き場所から辿る。** 古いリポジトリ（このスキル自体が同梱されていない）を更新するときに使うことが多いので、相対パス（`.claude/skills/...`）では見つからない。`$HOME/.claude` も使わない——Windows の Claude Code から WSL の bash を呼ぶと、`$HOME` は空の別ディレクトリを指す。
- 引数に `--check` があれば**上書きせず差分だけ**報告して終わる（step2 以降はスキップし、「引数なしで再実行すると適用します」と案内する）。
- 終了コード: `0`=最新（更新なし） / `1`=更新した（`--check` では差分あり） / `2`=テンプレを取得できなかった。
- **exit 2 のときは中断しない。** 取得できなかった理由（`gh auth login` が要る／オフライン／`TEMPLATE_REPO_PATH` でローカルのクローンを指定できる）をそのまま伝えて終わる。

## step2: 結果の解釈と報告

スクリプトの出力をそのまま貼らず、**何が変わったか**を要約する:

- **新規に入ったスキル**（`＋`）と**更新されたファイル**（`↻`）を分けて挙げる。件数が多いときはスキル単位にまとめる。
- ⚠️ で報告された「テンプレに無いファイル」があれば、**このリポジトリ独自のものか、廃止済みで消し忘れているか**を1行添える（判断できなければ、そのまま人間に委ねる）。
- 更新が無ければ「最新でした」と一言で終える。

### ★実行中のスキルが更新された場合の扱い

スクリプトが **`★ power/SKILL.md 自身が更新されました`** を出した場合、あるいは**いま実行中のワークフローのスキル**が更新対象に含まれていた場合は、必ずこう伝える:

> スキルの本文は**呼び出した時点でコンテキストに読み込まれる**ため、**いま動いているものは古い指示のまま**動き続ける。ファイルは新しくなっているので、**次に呼び出すときから**新版になる。

- したがって、**進行中のワークフローがあるなら、いったん区切って呼び直す**ことを勧める（`/power` を再実行する、`/clear` して次の工程から入り直す 等）。
- 逆に、これから呼ぶスキル（`power1` 〜 `power6` など）は**呼び出し時にディスクから読まれる**ので、そのまま進めて構わない。
- **新規に追加されたスキルは、登録されるまで少し遅れることがある**（直後に呼ぶと「Unknown skill」になりうる）。その場合は一呼吸おいて呼び直せばよい旨を添える。

## step3: コミット（git 管理下のみ）

更新があった場合、**コミットするかを AskUserQuestion で確認**する。既定の推奨は **`chore: sync skills from template` の単独コミット**:

- **機能の差分に混ぜない。** own リポジトリでは `.claude/` が PR に載るため、スキル更新が機能レビューのノイズになる。
- **いまトランク上にいる場合は注意を添える**（このプロジェクトはトランクベースで、変更は PR 経由が原則）。作業ブランチ上なら、そのブランチに単独コミットしてよい。
- OSS 本家（upstream）向けの PR では `.claude/` は power6 が除外するので影響しない。
- コミットしない選択も普通に有効（次のコミットのついでに入れる／まず動作を見たい）。その場合は「未コミットのまま残る」ことだけ明示する。

## 環境前提

- 対象リポジトリのルートで実行する。WSL の bash 推奨。
- **取得元は `template.conf` の `TEMPLATE_REPO`**（リポジトリ直下の `.claude/skills/template.conf`、無ければスクリプトと同じスキル一式のもの。`$HOME/.claude` では探さない——Windows の Claude Code から WSL を呼ぶと別ディレクトリを指すため）。スクリプトに個人名・組織名を決め打ちしないための設定で、社内などへ展開するときはこの値だけを書き換える。書式は gh と同じ `[ホスト/]オーナー/リポジトリ`（ホスト付きなら GitHub Enterprise Server として取得する）。
- テンプレートが private なら **`gh` 認証が必要**（`gh auth login`。Enterprise Server なら `--hostname`）。認証できない環境では、ローカルにテンプレのクローンがあれば `TEMPLATE_REPO_PATH=<path>` で代用できる。
- **コンテナ内で `~/.claude` にも repo にもスキルが無い**場合、本スキル自体が存在しないので使えない。その場合だけ `power/README.md` の手動 bootstrap（sparse-checkout でのコピー）を案内する。

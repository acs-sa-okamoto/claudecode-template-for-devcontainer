# AI開発用 セキュリティ・ガードレール（AI常時参照版）

このプロジェクトでコードを書く際の最低基準。
**P0 への違反は実装完了とみなさない。**

---

## 0. このルールの使い方（最優先）

- これは**最低基準**であり、課題解決の質を犠牲にしてまで形式的に満たすものではない。
- **適用しないと判断した規則は、黙って飛ばさず「なぜ不要か」を一言述べること。**
- セキュリティ要件と機能要件が衝突する場合は、勝手に決めず**人間に確認すること。**
- 優先度：**P0（絶対）> P1（原則）**。「参考」はAIの実行範囲外であり、文脈として認識するもの。
- **プロジェクト種別による適用範囲**：本ガードレールは Web/API/DB アプリを主な対象とする。CLI ツール・ライブラリ・データパイプライン・組み込み等では該当しない P0/P1 が多い。**該当しない規則は上記ルールに従い「なぜ不要か」を一言述べてスキップすること。**

---

## P0 — 絶対遵守（違反＝一発アウト）

コード上で直接守れる、かつ致命的な項目。

### 認証・認可
- 認証・認可は**必ずサーバー側**で実施する。スキップ・無効化・テスト用バックドア・管理者権限のハードコードは禁止。
- 「ログイン済み」と「アクセス権あり」を**別々に**判定する。
- **オブジェクトレベル認可（IDOR/BOLA）**：リソースアクセス時は、ロールに加えて「**そのデータの所有者か／権限があるか**」を ID ごとに検証する。
- 権限・課金・契約・ロール判定を**フロントエンドのみ**に依存しない。
- パスワードは平文保存禁止。**bcrypt または Argon2** でハッシュ化する。

### シークレット
- APIキー・パスワード・秘密鍵・トークンを**直書きしない**。
- シークレットを **Git リポジトリ／クライアント** に含めない。
- 環境変数または Secret Manager で管理する。
- **取得・設定が必要な APIキー・トークン・環境変数は、beam2 が生成する `prep.md`（ユーザー準備タスク）に列挙する**。実装側で勝手にダミー値や仮のキーを埋め込まない。

### インジェクション・コード実行
- SQL/NoSQL/OS/LDAP へ**文字列連結で入力値を渡さない**。ORM または Prepared Statement を使う。
- `eval()` ・動的コード実行を使わない。
- 出力時はエスケープし、XSS を防ぐ。

### 暗号
- 暗号・認証・ハッシュを**自前実装しない**。実績あるライブラリ／プラットフォーム機能を使う。

### ログ
- パスワード・トークン・APIキー・個人情報・機密情報を**ログに出力しない**。

## P1 — 原則（既定値。リスクに応じて判断し、逸脱時は理由を明記）

### 入力・出力
- 信頼境界（外部入力の受け口）で**スキーマ検証**を行う。
- 受け取るフィールドは **allow-list で限定**する（Mass Assignment／権限昇格対策）。
- ファイルアップロードは拡張子・MIME・サイズを検証する。
- 外部 URL を取得する機能には **SSRF 対策**を行う。
- HTML 入力を許可する場合は信頼できるサニタイズライブラリを使う。

### 認可・セッションの既定
- **デフォルト拒否（フェイルクローズ）**。エラー時・判定不能時は安全側に倒す。
- 管理者向け API は一般 API と分離する。
- JWT は署名検証と有効期限検証を行う。セッション ID は十分なランダム性を持たせる。
- **セッション/認証トークンをブラウザの `localStorage`・`sessionStorage` に保存しない**。XSS が起きた瞬間に窃取されるため。**`httpOnly` + `Secure` + `SameSite` の Cookie** に置く。※ Cookie を使わず Bearer トークンをメモリ上だけで扱う設計なら該当しない（その旨を一言）。
- **状態を変更するリクエストに CSRF 対策**を行う（Cookie でセッションを持つ場合）。`SameSite=Strict/Lax` を既定とし、クロスサイト送信が必要な設計では CSRF トークンを併用する。※ Cookie を使わない API（Bearer のみ）は構造上該当しない。

### 通信・公開範囲
- HTTPS を前提とする。
- CORS にワイルドカード（`*`）を使わず、許可オリジンを明示する。
- 内部 API を認証なしで公開しない。
- **セキュリティヘッダーを設定する**。最低限 **CSP（Content-Security-Policy）**、加えて `X-Content-Type-Options: nosniff`・クリックジャッキング対策（`X-Frame-Options` または CSP の `frame-ancestors`）。CSP はインラインスクリプト/スタイルの扱いが実装方針に影響するため、**設計段階で方針を決める**（後付けは高コスト）。

### 悪用対策（リスクに応じて）
- **外部公開・認証前・コストの高い**エンドポイントにレートリミットとタイムアウトを設ける。
- ログイン等にブルートフォース対策を行う。
- ※内部限定・低リスクなものには**過剰実装しない**。実装/非実装の判断理由を残す。

### アーキテクチャ・業務ロジック
- フロントエンドから DB へ直接接続しない（必ず API 経由）。
- 価格計算・割引・在庫など重要な業務ロジックはサーバー側で実行する。

### 監査・依存関係
- 重要イベント（権限変更・課金変更・削除）を監査ログに記録する。エラーメッセージに内部構成情報を含めない。
- 依存関係は lockfile で固定し、必要最小限・信頼できるものに限る。未使用ライブラリは削除する。

## 参考 — チーム/インフラ運用（AIの実行範囲外。文脈として認識）

AI が 1 つの PR で制御できない、運用・組織側の規則。コード生成時の判断材料とする。

- 本番／開発環境を分離し、本番データを開発環境へ持ち込まない。
- 本番 DB をパブリックネットワークへ公開しない。SG/FW は最小ポート、IAM は最小権限。
- 脆弱性スキャン・シークレットスキャン・静的解析を定期実施する。
- 依存ライブラリの選定・自動アップデートの本番反映は人間が承認する。
- **AI 生成コードは人間がレビューし、最終責任を持つ。あなた（AI）は最終承認者ではない。**

## 完了条件（Definition of Done）

- 要件を満たしている。
- テスト・型チェック・Lint がすべて成功している。
- **P0 に違反していない。P1 の逸脱がある場合は理由が明記されている。**
- （CI ゲート）依存脆弱性チェック・シークレットスキャンが成功し、人間レビューが完了している。

### beam ワークフローへの継承

本ガードレール（特に P0）は、後続フェーズの完了判定に継承される。

- **beam4-tasks**：各タスクの完了条件に「該当する P0 を満たすこと」を含める。
- **beam5-implement**：実装の Definition of Done に「P0 違反なし／P1 逸脱は理由明記」を必須チェックとして組み込む。

# 案導出チェックリスト（scope-options 用）

リッチ案・フル案の候補を**列挙可能なソース**から出すためのチェックリスト。**チェックリスト外の追加は「その他（要根拠）」枠に明示し、根拠が書けなければ落とす**（思い付き排除の核心）。

## EN-*: 強化チェックリスト（リッチ案用）

**適用規則**: 既存機能1つずつに EN-1〜6 を照らし、「**どのユーザーストーリー（US-*）の体験を強化するか**」を答えられる候補だけ採用する。新領域（新しいジョブ）は足さない——それはフル案（DS-*）の領分。

| ID | カテゴリ | 走査する問い（例） |
|---|---|---|
| EN-1 | 回復性 | 誤操作を取り消せるか（アンドゥ）／途中状態を失わないか（下書き・自動保存）／一時失敗に自動リトライがあるか |
| EN-2 | フィードバック | 長い処理に進捗が見えるか／完了・失敗が通知されるか／他所の変更がライブ反映されるか |
| EN-3 | 探索性 | 目的の項目にすぐ辿り着けるか（検索・フィルタ・ソート）／大量データでページングがあるか |
| EN-4 | 入力効率 | 一括操作できるか／自動補完・既定値・ショートカットがあるか／再入力を強いられないか |
| EN-5 | 性能体感 | 体感待ち時間を削れるか（キャッシュ・遅延読込・楽観更新） |
| EN-6 | 見た目・快適さ | テーマ・表示密度の調整／アクセシビリティ（キーボード操作・コントラスト） |

## DS-*: 発見チェックリスト（フル案用）

**適用規則**: 各カテゴリを網羅走査する。採用候補には必ず **DS-ID とコアジョブとの関係**（直結／支援／周辺）を記す。周辺のものは「将来必要になる蓋然性」を一言で根拠づける。

| ID | カテゴリ | 走査する問い（例） |
|---|---|---|
| DS-1 | ライフサイクル | 初期セットアップの支援は要るか／既存データの移行は／バックアップ・復元は／アーカイブ・退役は |
| DS-2 | 管理・運用 | 管理画面は要るか／監査ログは／利用統計は／ヘルスチェック・監視は／設定の UI は |
| DS-3 | 連携・拡張 | API 公開は／Webhook は／エクスポート・インポートは／他サービス連携は |
| DS-4 | 複数化・スケール | 複数ユーザー・権限（ロール）は／多言語は／複数環境（dev/prod）は |
| DS-5 | 品質・保守 | E2E テストの拡充は／性能テストは／エラーレポート収集は |
| DS-6 | **スコープ外の再評価** | **PRD 第10章「スコープ外」の各項目を1つずつ**「フル案でなら入れるべきか」評価する（一度検討して除外された機能の在庫＝最有力の発見源） |

## 記載様式（マトリクスへの反映）

- 追加候補のセルには `採用（出典: EN-2 / US-03 の体験強化）` `採用（出典: DS-6 / スコープ外#4 の再評価）` のように**出典 ID を必ず併記**する。
- チェックリスト外の候補は最後に「**その他（要根拠）**」節へ分離し、根拠（誰のどんなジョブに効くか）を書けたものだけマトリクスに昇格させる。

# 改定記録（Revision Record）出力テンプレート

このファイルは `revise` スキルが改定記録を生成する際の書式定義です。**1回の改定＝1ファイル**（監査証跡）。出力先は `docs/revisions/{YYYY-MM-DD}-{slug}.md`（同日複数回は slug で区別）。仕様ファイル側の変更履歴には本ファイルへの**1行リンクのみ**を書く（内容を二重管理しない）。

---

## 出力テンプレート

以下に従って生成する。`[...]` は実際の内容で置き換える。

````markdown
# 改定記録: [対象ID or 対象] — [要約]

**日付:** YYYY-MM-DD
**対象:** [beam 要件名 or power 機能名]（[beam / power]）
**入口:** [意図先行 / 事後検出（git diff）]
**改定時の進捗段階:** [仕様のみ / 設計済み / タスク分解済み / 実装済み（conformance あり）]

---

## 1. 変更内容（Before → After）

| ID | Before | After |
|---|---|---|
| REQ-05 | [旧文言の要約] | [新文言の要約] |

[廃止・新規があれば: 廃止 → `~~REQ-XX~~ ❌(廃止: 理由)` / 新規 → REQ-NN を追加]

## 2. 影響リスト（承認済み）

> 凡例: 色は「**影響あり」という判断の確からしさ**（🔵確実=直接IDリンク / 🟡妥当な推測=ファイル・モジュール経由 / 🔴推測=語彙のみ・既定では対処しない）

| 色 | 成果物 | 根拠（導出元） | アクション |
|---|---|---|---|
| 🔵 | AC-03 | 仕様内参照（AC-03 → REQ-05） | 文言更新 |
| 🔵 | TASK-0007 | カバレッジ行列 REQ-05→TASK-0007 | 更新・再キュー |
| 🔵 | conformance REQ-05 行 | conformance-report | ⏳ 要再検証に変更 |
| 🟡 | TASK-0012 | implements 記録（同一ファイル src/foo.ts） | 確認の上 更新 |
| 🔴 | [成果物] | [語彙一致] | 対処せず（参考） |

## 3. 実施したアクション

- 仕様更新: [ファイルと ID]
- 設計再生成: [ファイル一覧。なければ「なし」]
- TASK 更新: [N] 件 / 新規: [K] 件 / 廃止: [M] 件（削除タスク起票: [有/無]）
- tasks.db: 再キュー [N] 件（status→ready・update_badge=1）
- conformance-report: [M] 行を ⏳ 要再検証化
- prep.md / understanding-brief: [同期内容。なければ「変更なし」]

## 4. 再キューしたタスク

| TASK-ID | 旧 status | 新 status | 理由 |

| TASK-0007 | done | ready | REQ-05 改定（集約ウィンドウ 5s→10s） |

## 5. 残作業（次アクション）

- [ ] `/beam5-implement`（または `/power5-implement [機能名]`）で再キュー分を再実装
- [ ] ゲート（beam5 step4 / power6）で再検証（⏳ 行の解消）
````

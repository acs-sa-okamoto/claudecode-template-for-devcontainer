# 標準デザイン（デザイン刷新の指針）

> slide-maker **step3（デザイン刷新）** が使う。**毎回、下記の標準デザインを適用する**（旧・方向カタログA/B/Cからの選択は廃止済み）。内容（outline.md のテキスト・枚数・順序）は一切変えない。
> step3 はこの標準を元に、デッキ固有の値（縦ラベルの語など）を埋めた `design-spec.md` と `design-mock.html` を作業フォルダに書き出す。以降の工程では design-spec.md が **style-guide.md より優先**され、モックも **PPTXで表現可能なトークンのみ**で描く。
> 出自: 無料配布されていたスライド見本にユーザーが手を加えた `Biz Vault/デザイン見本.pdf` のトークン翻訳（2026-07 確定）。
> **品質の土台は `visual-rubric.md` の B層・C層**。チェック専用ではなく、生成時から目指す基準である。

## コンセプト

**ダスティブルー×黒×白の3色だけ**。鮮やかなアクセント色を使わず、強調は黒の太字とサイズで作る。角丸ゼロ・フラット・余白広く・左重心。英語は意匠、日本語は情報。

## パレット（役割 → hex）

| 役割 | hex | 用途 |
|---|---|---|
| pale（ダスティブルー） | `CBD8E5` | 表紙・締めの**全面背景**／白ページ上の面（ノード・バー）／円の**太いリング**／箇条書きドット |
| bg（本文） | `FFFFFF` | 本文ページの背景・円の面・強調ボックスの面 |
| ink | `0F1115` | 見出し・本文・タグ。**強調も黒**（太字・サイズで差を付ける） |
| muted | `6B7280` | リード・キャプション・矢印（白背景上） |
| muted-on-pale | `4B5563` | 淡青背景上の小さめテキスト（コントラスト確保） |
| hairline | `E5E7EB` | 罫線・表の区切り |
| 強調枠 | `0F1115`（0.75〜1pt 細枠） | 強調ボックス＝白面＋黒細枠 |
| 意味色 | 文脈に従う | 意味を持つ色のみ許可（例: 信頼性🔵🟡🔴= `2E7DE0`/`E0A800`/`D03030`、問題の✕= `DC2626`） |

## タイポグラフィ（役割 → フォント・サイズ・太さ・色）

| 役割 | フォント | サイズ | 太さ | 色 |
|---|---|---|---|---|
| 表紙タイトル | BIZ UDPGothic | 44 | 太 | 0F1115 |
| 本文タイトル | BIZ UDPGothic | 30 | 太 | 0F1115 |
| リード | BIZ UDPGothic | 15 | 標準 | 6B7280 |
| 本文 | BIZ UDPGothic | 12.5–14 | 標準 | 0F1115 |
| 縦ラベル（EN） | Segoe UI | 10.5 | 太・字間広め | 0F1115 |
| 右下タグ（目的タグ等） | BIZ UDPGothic | 11 | 太 | 0F1115 |
| 特大数字・欧文 | Segoe UI | 文脈に従う | 太 | 0F1115 / 6B7280 |

- **縦ラベル語はデッキごとに step3 で決める**: 本文ページ左端（90°回転・上→下）に、そのスライドの主題を表す**英語1語**（例: Problem / Overview / Phases…）。表紙・締めには付けない

## 図形言語

- **角丸ゼロ**（すべてシャープな矩形）。影・グラデーションなし
- 面 = ダスティブルーのべた塗り（枠線なし）
- **強調 = 白面＋黒細枠**（塗りで強調しない）
- 円 = **白面＋太いダスティブルーのリング**（6〜8pt）
- 箇条書きの点 = 小さなダスティブルーのドット
- **見出し下の罫は使わない**（visual-rubric C層を優先）

## レイアウト

- 余白: 左右 1.0in 以上。左揃え・左重心（中央揃えの多用禁止）
- **表紙と締め（最終スライド）= ダスティブルー全面背景／本文 = 白背景**（淡青↔白の交互リズム）
- 本文ページの左端に縦ラベル（意匠。コンテンツはその右から始める）
- 右下タグ（目的タグ等）: 黒太字・下辺から 0.35in 以上
- CTA: 白面＋黒細枠の矩形

## Do / Don't

- Do: 強調は黒の太字とサイズで（1スライド1強調）
- Do: 意味を持つ色（🔵🟡🔴・✕ 等）は維持する
- Do: 淡青は「構造の色」として使う（背景・面・リング・ドット）
- Don't: 鮮やかなアクセント色を持ち込まない
- Don't: 角丸・影・グラデーション
- Don't: 見本のロゴ・固有ビジュアルの複製／見出し下の罫線

## 例外: 別デザインの見本を指定された場合（リファレンス翻訳）

ユーザーが**明示的に**「このデッキは別のデザインで」と見本（URL・画像・PDF・CSS・既存デッキ）を指定した場合のみ、次の手順で標準を上書きする:

1. **抽出**: 背景色・文字色・アクセント色（最大2）／書体の雰囲気（幾何学サンセリフ・明朝・等幅）／角丸・線の太さ／密度（余白量）／特徴的モチーフ（1つだけ）
2. **PPTXで表現できない効果は代替に置換**: blur・グラス効果 → 薄ティントのべた塗り／グラデーション → 単色 or 面の重ね／アニメーション・ホバー → 無視
3. **標準デザインをベースに**、抽出したトークンで上書きする（ゼロから発明しない）
4. ブランドロゴ・固有ビジュアルの複製はしない（**雰囲気の翻訳**に留める）
5. **フォントは実機にあるものだけ**使う（BIZ UDPGothic / Yu Gothic / Meiryo / Yu Mincho / Segoe UI / Consolas。無い Web フォントは最も近い和文フォントに置換）
6. 抽出結果（パレット・書体・形・モチーフ）を提示して**確認を取ってから** design-spec.md に固化する

## design-spec.md の出力形式（step3 が書き出す契約）

通常は標準デザインの値をそのまま確定し、デッキ固有の値（縦ラベル語・タグの文言など）を追記する。章立て:

```markdown
# Design Spec: <資料タイトル>
- 適用デザイン: 標準デザイン（assets/design-directions.md）／（例外時のみ）見本の要約

## パレット（役割 → hex）
## タイポグラフィ（役割 → フォント・サイズ・太さ・色）
## 図形言語
## レイアウト（縦ラベル語の割り当てを含む）
## Do / Don't
```

- 以降の工程では **design-spec.md が style-guide.md より優先**される
- `visual-rubric.md` の B-5（パレット規律）は **design-spec.md のパレットを基準**に判定する

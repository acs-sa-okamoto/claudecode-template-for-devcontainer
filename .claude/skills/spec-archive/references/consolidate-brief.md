# 領域のまとめ込みの依頼文（サブエージェント向け）

step4 で、領域ごとに general-purpose のサブエージェントへ渡す。`{…}` を埋めて使う。
1 本で 1 領域。並行は 4 本まで。サブエージェントは領域のファイルを**直接書き**、網羅チェックまで済ませて、要約だけを返す。

---

あなたは、既存システムの仕様を整理する担当です。完了した機能の要件を、現役の仕様の 1 領域にまとめます。

## 書くファイル

- `docs/spec/current/{英名}.md`（{領域名}）。{新規なら: テンプレート `{テンプレートの絶対パス}` に従って新しく作る ／ 既存なら: 今の内容を残し、足して直す}
- この領域の範囲: {main が決めた範囲。1〜2 文}
- ほかの領域（同時に別の担当が書いている）: {英名: 範囲 の一覧}。範囲の外の要件は書かず、「別の領域の候補」として報告する

## 読むもの（まとめる元）

{この領域に関わる元の文書と、そこにある ID の範囲の一覧。例:
- docs/spec/my-app/requirements.md の REQ-001〜020・NFR-001〜005 / acceptance-criteria.md の対応する節
- docs/spec/wordbook-v2-overhaul/feature-requirements.md の FR-01〜08・AC-01〜06・CON-01〜05
- docs/spec/bucket-split-nav-sounds/feature-requirements.md の FR-01〜04}

あわせて読む:
- 改定記録 `docs/revisions/` のうち、上の ID に触れるもの: {ファイルの一覧}
- 地図帳の関わる区画のページ: {docs/code-atlas/sections/… の一覧}（今のコードの姿の確認に使う）

## まとめ方（必ず守る）

1. **ID は変えない。** 元の ID に出典の名前を全角かっこで添える: `REQ-017（my-app）`・`FR-11（app-guide-onboarding）`。番号を振り直さない（コードとテストのコメントが元の ID を参照している）。
2. **新しいものが勝つ。** 後の機能や改定記録が同じ要件を変えていたら、新しい方の内容で書く。ID は元のまま、出典に「→ {後の機能名} で上書き」と足す。上書きした側の ID（例: `FR-03（後の機能）`）も、同じ見出しの中か受け入れ基準に書き、別の見出しにはしない（1 つの要件は 1 か所）。
3. **今のコードと照らす。** 次を実行し、出てきた節は今の動きに合わせて書く（部品の名前が変わっただけなら新しいパスに、機能ごと無くなったなら「しないこと」に回すか、まとめない）。
   ```bash
   bash {スクリプトの置き場所}/find-stale-spec.sh {元の文書のパス …}
   ```
   判断できないものは 🔴 にし、報告の「確かめること」に入れる。**推測で要件を足さない・変えない。**
4. **入れないもの:** 統合点（INT）・回帰（REG）・ユーザーストーリー（US）・テストケース（TC）・作業のための制約（「既存の X に合わせる」など）。作業のための制約（CON など）を入れないときは、`docs/spec/ARCHIVE.md` の「まとめなかった ID」に `- CON-03（名前）: 理由` の形で書く（main がまとめて書くので、報告に挙げるだけでよい）。
5. **しないこと（スコープ外・禁止）を落とさない。** 「〜しない」「〜してはならない」は、理由と前提を添えて「しないこと」の節に書く。power2 の矛盾チェックがここを読む。
6. **廃止された要件**（取り消し線や改定記録で廃止されたもの）は、取り消し線で残す。
7. **出典はパスではなく名前で書く**（元の文書は片付けて Git の履歴に移るため）。
8. 信頼性レベル（🔵🟡🔴）は元の文書のものを引き継ぐ。

## 終わる前に（必ず実行する）

```bash
bash {スクリプトの置き場所}/check-current-spec.sh {--target 名前 を、この領域の元の機能ごとに}
```

- ほかの領域の担当がまだ書いていない ID は「抜け」に出るので、**この領域の範囲の ID だけ**を見る。範囲の ID に抜けがあれば直す。
- 見出しの重複があれば直す。

## 報告（これだけを返す。ファイルの中身は返さない）

- 書いたファイルと、要件の数（機能・非機能・制約・しないこと）
- まとめなかった ID と理由（`- ID（名前）: 理由` の形。main が ARCHIVE.md に書く）
- 別の領域の候補（範囲の外だった ID）
- 新しいものが勝った箇所（どの ID をどの機能が上書きしたか）の数と、主なもの 3 件
- 古い記述として直した節の数と、主なもの 3 件
- 確かめること（🔴 にした項目と理由）
